The final Release workflow completed successfully in [run 34229389858](https://github.com/gh615280-maker/TextbookLens/actions/runs/34229389858). The downloaded checksum file was compared with GitHub's four installer digests and matched every asset.

## Automated gates

- Frontend and script suite: 100 files and 411 tests passed.
- Browser end-to-end suite after the reader-layer regression: 67 passed and one opt-in external-material test remained skipped.
- Rust release validation: 490 tests passed; three environment/manual tests were ignored by default.
- TypeScript, ESLint, Prettier, Rust formatting, release Clippy, generated-binding byte consistency, dependency policy, licenses, fixtures, and sensitive-file checks passed.
- `@xmldom/xmldom` was updated to 0.8.15 and the reviewed GHSA-6gmq-8vp8-gcm6 policy remained enforced; production npm audit reported zero vulnerabilities.
- The final distribution scan passed for 285 files and approximately 580 MB of standard/offline package inputs. No user textbook, user database, credential, model weight, source path, debug tool, or test-only application entered the public assets.

The first tag-triggered release attempt exposed CRLF conversion on the Windows runner. Repository-wide LF checkout rules and a Windows format gate fixed it. The second attempt exposed an 8.3 TEMP alias in artifact-audit test fixtures; the fixture root was canonicalized without weakening production alias, junction, race, or hard-link rejection. Both fixes passed pull-request CI before the final tag workflow. Before the GitHub Release existed, the tag briefly referenced `4f723eee` and `19d15ec`; the published release and assets use the final `b98c9faf` target.

## Windows installation and upgrade

Tests used isolated Windows Sandbox environments with separate application data and user libraries.

- On a clean machine without WebView2, the complete offline EXE installed, launched, and uninstalled; the complete offline MSI installed and launched.
- Standard EXE and MSI packages installed, launched, and uninstalled without network access on a machine that already had WebView2.
- A v0.1.0-to-v0.2.0 EXE upgrade migrated the database from schema 15 to 17 and preserved the imported DOCX, annotations, question history, retrieval fragments, settings, provider configuration, and saved credentials. SQLite integrity and foreign keys remained valid.
- After upgrade, a DOCX table-of-contents jump kept the reader toolbar visible.
- A scanned PDF opened with packaged decoder resources, and sampled pages rendered without external resource requests.
- Source textbooks used for the isolated checks retained their pre-test SHA-256 values.

These checks do not turn uninstall into a data-erasure guarantee. Users should run **Clear all data** when the goal is to remove TextbookLens local data and credentials.

## Local model checks

- Installed Ollama discovery, credential-free profile registration, and a complete streamed text answer passed with Ollama 0.33.3 and `deepseek-r1:8b`.
- An isolated loopback port verified automatic Ollama service startup and discovery of already downloaded models. The test-owned service was stopped afterward; the normal user service was not stopped.
- Ollama/Qwen3-VL 4B completed image requests through the release provider runtime and local adapter. A mathematics sample correctly identified that a sequence term approaching zero is necessary for series convergence.
- A dense public-economics subsidy chart returned a fluent but factually reversed efficiency-loss comparison. This is an explicit quality failure: successful local inference does not imply answer correctness.
- Oversized input rejection, active-request cancellation, and retry after cancellation passed at the application-adapter layer. The complete set of native-UI combinations was not exercised.

## Boundaries and remaining work

- LM Studio filtering and streaming have automated coverage, but real-machine text validation is deferred to v0.2.1. LM Studio vision is not promised.
- No real RAM/VRAM exhaustion stress test was run.
- Not every page, handwritten formula, chart, or native-UI visual cancel/retry combination was tested.
- The network-assisted WebView2 acquisition path of the standard small installer was not independently validated on a machine without WebView2; use the offline package for disconnected clean installation.
- Large scanned PDFs may require manual zoom adjustment. Automatic fit-to-width is not implemented.
- Normal PDF text layers, EPUB, and DOCX text extraction do not need an AI model. Local whole-book OCR and local whole-book visual indexing are not implemented. Confirmed whole-book scan analysis still uses a configured cloud provider that supports that operation.
- Packages are unsigned; successful isolated installation does not create Windows download reputation.
- Five cloud-provider real-credential gates were not run. Synthetic/loopback protocol coverage is not evidence of current account access, quota, availability, retention behavior, price, or answer quality.

Conclusion: v0.2.0's public source, standard packages, offline packages, primary reading fixes, local Ollama text path, and bounded local vision transport passed the recorded gates. Local vision remains an assistive feature and must not be described as reliable for all formulas, handwriting, charts, or subjects.
