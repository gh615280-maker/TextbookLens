# TextbookLens V1 完整可执行验收标准

**版本：** 1.0
**日期：** 2026-08-08
**适用平台：** Windows 11 x64
**目标：** 将正式规格、主控台重规划、界面决定、A–Q 验证矩阵、Phase 15 发布计划和当前实现统一为可逐项执行、可复现、可判定的 V1 验收基线。

## 1. 验收结论

V1 只有在以下条件全部满足时才能判定为 **PASS / 可发布**：

1. 本文所有标记为“必须”的用例均为 PASS；BLOCKED、NOT RUN 和无证据的口头确认均不算 PASS。
2. A–Q 端到端场景全部通过，且自动化部分与 Windows 11 手工门禁均有可复现证据。
3. PDF、EPUB、DOCX 三种格式，`zh-CN`、`zh-TW`、`en` 三种语言均完成覆盖。
4. OpenAI、Gemini、Anthropic、DeepSeek、Kimi 五家服务商的文本能力均完成真实凭据最小门禁；视觉和结构化能力只对已核实支持的模型验收。
5. 安装、升级、重启、离线、备份恢复、删除、清除、隐私、可访问性和发布产物门禁全部通过。
6. 自动化全绿，Release 安装包可在干净的 Windows 11 x64 环境安装、运行、卸载并复现。
7. 没有 P0/P1 缺陷，没有未关闭的数据丢失、凭据泄漏、跨教材串数据、静默上传或破坏性边界缺陷。

任一必须项失败即为 **FAIL / 不可发布**。对官方能力为未知或明确不支持的模型，应显示安全门控且不发请求；该结果记为 `DENIED/PASS`，不能伪造能力成功。

## 2. 权威依据与冲突规则

验收依据按以下优先级解释：

1. 当前开发机桌面 `textbooklens.lnk` 实际启动版本中已经确认的用户功能行为
2. [V1 正式规格](../superpowers/specs/2026-08-03-textbooklens-v1-replanned-design.md)
3. [重规划变更包](../superpowers/specs/2026-08-03-textbooklens-replanning-change-package.md)
4. [界面与阅读器交互决定](../superpowers/specs/2026-08-03-textbooklens-interface-decisions.md)
5. [Phase 15 发布计划](../superpowers/plans/2026-08-03-textbooklens-replanned-phase-15-release.md)
6. [现有验证矩阵](2026-08-03-textbooklens-replanned-verification-matrix.md)
7. 当前产品实现和自动化测试

桌面快捷方式只作为本次 V1 产品行为 checkpoint 的需求真相：必须只读记录其目标、参数、工作目录、目标二进制哈希/时间戳，并证明最终源码可复现已确认行为。它指向开发构建时，不得据此把 Release 安装、干净 Windows、签名、卸载或真实 provider 门禁记为 PASS；快捷方式本身也不得在验收中修改。

旧方案中的“先配置服务商再导入”“固定右侧 AI 面板”“关闭面板即取消”“普通文本操作先弹阻断式请求预览”均已失效，不得作为验收预期。

### 2.1 明确不在 V1 验收范围

- Windows 10、网页端、移动端；
- 账户、登录、云同步、多人协作；
- 项目自建 AI 代理服务、代付模型费用或远程索引作为权威副本；
- 未经用户主动操作的后台教材上传；
- 本地 OCR 引擎、闪卡、间隔重复、自动评分、TTS、Agent；
- 把 AI 描述冒充教材原文，或让重新索引静默覆盖人工修正。

这些能力不存在不构成缺陷；如果产品界面、文档或安装包声称已经支持，则按误导性发布声明处理并阻断发布。

## 3. 状态、严重级别与证据规则

### 3.1 状态

| 状态        | 定义                                                             |
| ----------- | ---------------------------------------------------------------- |
| PASS        | 实际执行完成，全部预期成立，证据可复现                           |
| FAIL        | 任一必要预期不成立，已记录复现步骤和安全错误信息                 |
| BLOCKED     | 因环境、账户或外部服务无法执行；不是 PASS                        |
| NOT RUN     | 尚未执行                                                         |
| DENIED/PASS | 未知或不支持能力在请求前被安全阻止，且没有网络请求或持久化副作用 |
| N/A         | 仅允许用于正式规格明确排除的范围，必须写明依据                   |

### 3.2 缺陷级别

| 级别 | 判定示例                                                                                  | 发布处理                                 |
| ---- | ----------------------------------------------------------------------------------------- | ---------------------------------------- |
| P0   | Key/正文/图像泄漏；跨教材数据；删除用户原文件；备份破坏当前数据；未授权后台上传；伪造完成 | 立即阻断                                 |
| P1   | 核心流程不可完成；完成对话丢失；失败结果被持久化；三种格式之一不可用；关键键盘流程不可用  | 阻断                                     |
| P2   | 非核心操作错误、明显布局溢出、局部翻译/状态错误，有安全替代路径                           | 默认阻断，修复或书面豁免后重验           |
| P3   | 不影响任务完成的轻微视觉问题                                                              | 可记录为非阻塞，但必须确认不影响可访问性 |

### 3.3 证据

每个用例至少记录：用例 ID、日期、Git HEAD、应用版本、环境、执行人、状态、实际结果、自动化命令或操作步骤、非敏感证据位置、关联缺陷。

证据中禁止出现：

- API Key、Credential Manager 条目名或可反推凭据的信息；
- 真实教材正文、页面图像、用户批注、教学指令、问题、回答或完整上下文；
- provider 原始响应正文、远程资源 ID、绝对私人路径；
- 未脱敏日志、SQLite、备份或截图。

截图和录屏只使用项目自制 fixture。真实 provider 门禁只记录 provider、model、能力、规范化状态、时间和请求计数。

## 4. 验收环境与测试数据

### 4.1 必备环境

- 一台开发验证机：Windows 11 x64，可运行 Node、Rust、Chromium、Tauri 构建。
- 一台干净验收环境或全新 Windows 用户配置：未安装 TextbookLens、无旧应用数据、无 TextbookLens 凭据。
- 第二个干净 Windows 用户配置：用于备份恢复和凭据缺失验证。
- 系统显示缩放：125%、150%、200%；至少一个 200% 的真实系统缩放证据。
- 窗口宽度：320、480、768、1024、1440 及以上逻辑像素。
- 普通主题、深色主题、高对比度/强制颜色、关闭透明效果、减少动画。
- 键盘、鼠标；Windows Narrator 或 NVDA 至少一种屏幕阅读器。
- 可断开/恢复网络的环境。
- 五家 provider 的专用低权限测试凭据；不得使用个人生产凭据。

### 4.2 固定测试数据

| 数据                                         | 用途                                   |
| -------------------------------------------- | -------------------------------------- |
| `fixtures/textbook.pdf`                      | 正常 PDF 导入、阅读、选择、搜索        |
| `fixtures/textbook.epub`                     | EPUB 导入、阅读、锚点和区域选择        |
| `fixtures/textbook.docx`                     | DOCX 导入、阅读、锚点和区域选择        |
| `fixtures/source/scanned-textbook.pdf`       | 扫描 PDF、拒绝或执行 AI 辅助索引       |
| `fixtures/source/mixed-quality-textbook.pdf` | 部分失败、待复核、重试和来源区分       |
| `fixtures/source/figure-energy.png`          | 有界图表区域视觉请求                   |
| loopback provider fixtures                   | 确定性流、失败、截断、取消、结构化返回 |
| 两本内容可区分的自制教材                     | `book_id` 隔离和跨书泄漏检查           |
| 恶意/损坏 `.tlbackup` 测试包                 | 哈希、版本、路径穿越、大小和回滚校验   |

所有手工测试应从已知干净状态开始。除专门的升级/恢复用例外，不允许复用上一个用例遗留的数据来获得 PASS。

## 5. 执行顺序

1. 记录基线：Git HEAD、工具版本、工作树状态、测试环境和 fixture 哈希。
2. 运行静态检查、单元/集成测试和确定性 E2E。
3. 执行本文功能用例和 A–Q 端到端场景。
4. 执行重启、离线、并发、故障注入和破坏性边界。
5. 构建 Release 安装包并做产物隐私扫描。
6. 在干净 Windows 11 x64 环境执行安装、真实显示缩放、可访问性和五家 provider 手工门禁。
7. 在第二个干净配置执行备份恢复和无凭据重连。
8. 汇总缺陷，修复后重跑直接受影响用例及相关全局门禁。

| ID     | 类型          | 操作                                                                       | 通过标准                                                                                                        |
| ------ | ------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |

| PRO-04 | 自动+手工     | 用有效新 Key 替换旧 Key，并注入验证、凭据写入、数据库写入、旧 Key 删除失败 | 验证成功后才写入；任一步失败保持旧 profile 可用或完全回滚新凭据；不出现双份未知状态                             |
| PRO-05 | 自动          | 删除非活动和活动 profile                                                   | 需要确认并清除对应凭据；活动 profile 安全回退或进入未配置状态；历史 provider/model 元数据不被改写               |
| PRO-06 | 自动          | 使用未知/自定义模型尝试视觉或结构化操作                                    | 只在文本验证后授予保守文本能力；视觉/结构化请求在凭据读取和网络前被拒绝                                         |
| PRO-07 | 自动          | 设置页面图像、AI 索引、费用风险“不再提示”，切换 profile，再恢复全部提示    | 偏好按 profile+类别隔离；同 profile 同类别生效；切换 profile 后重新确认；恢复后再次提示                         |

| PRO-09 | 自动          | 断网、超时、限流、鉴权失败、响应损坏后重试                                 | 显示稳定错误码和安全本地化文案；不显示 vendor body；不会把失败当完成；恢复网络后必须由用户重新发起              |
| PRO-10 | 自动+真实门禁 | 只输入一次国内 Kimi Key；再以独立 profile 输入一次国际 Kimi Key            | 不显示区域选择；先以无教材内容的 `GET /models` 探测；分别绑定 `cn`、`international`；探测阶段没有 `/files` 上传 |
| PRO-11 | 自动          | 国内探测返回明确鉴权/区域不适用、429、5xx、网络错误和超时                  | 只在明确鉴权/区域不适用时尝试国际端点；429、5xx、网络错误、超时保持原错误且不切区；两端鉴权失败安全返回         |
| PRO-12 | 自动+重启     | 保存后重启并执行聊天、Files 上传/轮询/内容下载                             | 区域以 `cn \| international` 受限枚举持久化；聊天与 Files 使用同一绑定区域；重启不重新猜 Key 或静默跨区         |
| PRO-13 | 自动          | 替换 Kimi Key，并让旧提取资源位于原区域                                    | 新 Key 必须重新探测；未完成提取绑定随配置变化；旧远程资源始终按创建区域删除，不因当前 profile 区域改变而误删    |
| PRO-14 | 自动+审计     | 扫描区域探测、提取和清理的 DB、日志、错误、DTO                             | 不保存任意 base URL；不记录 Key、Key 形态或远程 ID；SQLite 只保存安全区域枚举和随机 vault 引用                  |

## 10. Windows 11 手工验收脚本

在干净 Windows 11 x64 环境按以下顺序一次完成并录制规范化证据：

1. 安装并首次启动，确认无旧数据。
2. 切换三种语言各一次。
3. 导入 PDF、EPUB、DOCX；验证书库两种视图、搜索、打开和状态。
4. 断网；验证三本书可阅读、搜索、批注和查看历史；恢复网络不自动执行 AI。
5. 添加一个测试 provider；完成文字解释、图表框选确认、两个并发面板、隐藏继续、显式停止、续问和删除。

7. 打开教材级主控台；验证本地概览、整本提问、折叠历史、问题简述搜索和原文定位。
8. 在 125%、150%、200% 系统缩放，高对比度、关闭透明和减少动画下重复关键阅读/框选/面板流程。
9. 仅用键盘和 Narrator/NVDA 重复首次启动、解释、历史和备份确认。
10. 创建备份，在第二个干净配置恢复；确认无 Key 且需重新连接。
11. 删除一本书，确认原文件仍在；清除全部数据，确认凭据清理和回到首次引导。
12. 卸载并按产品承诺扫描残留；若产品未承诺卸载清除用户数据，应准确显示/记录保留策略，不自行扩大承诺。
