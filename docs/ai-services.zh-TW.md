# AI 服務與傳送邊界

[English](ai-services.md) · [简体中文](ai-services.zh-CN.md) · [繁體中文](ai-services.zh-TW.md)

TextbookLens 支援使用者設定的 OpenAI、Gemini、Anthropic、DeepSeek 和 Kimi 官方服務，也支援 [Ollama 本機文字／圖片模型和實驗性的 LM Studio 文字模型](local-models.zh-TW.md)。請求從 Rust 桌面層送出，瀏覽器介面不會直接請求服務商，也不能設定正式環境基礎位址。

新增或替換雲端金鑰時，應用程式會先驗證，再提交 Key/profile 更新。雲端金鑰保存在 Windows 認證管理員中，不進入 profile 清單、SQLite、前端狀態或備份。本機 profile 使用自動探索的回環連接埠，不需要雲端金鑰。

## 已設定的能力註冊表

下表是實作邊界，不是價格、額度、隱私、可用性或未來模型承諾。「頁面操作」要求經過驗證的文字、圖片和嚴格結構化輸出能力；僅支援原生 PDF 並不能啟用該操作。應用圖片上限為最多 4 張、每張 4 MiB、總計 12 MiB、任一邊不超過 4096 像素，每張解碼像素不超過 8,847,360。

| 服務商    | 預設模型            | 文字 | 圖片   | 原生 PDF | 嚴格結構化輸出 | 頁面操作 |
| --------- | ------------------- | ---- | ------ | -------- | -------------- | -------- |
| OpenAI    | `gpt-5.6`           | 支援 | 支援   | 支援     | 支援           | 支援     |
| Gemini    | `gemini-3.6-flash`  | 支援 | 支援   | 支援     | 支援           | 支援     |
| Anthropic | `claude-sonnet-5`   | 支援 | 支援   | 支援     | 支援           | 支援     |
| DeepSeek  | `deepseek-v4-flash` | 支援 | 不支援 | 不支援   | 嚴格工具支援   | 本機拒絕 |
| Kimi      | `kimi-k3`           | 支援 | 支援   | 不支援   | 支援           | 支援     |

未註冊或未知模型在驗證後只獲得保守的文字能力。圖片、PDF 和嚴格結構化能力預設關閉；應用程式會在讀取認證或存取網路前拒絕不支援的操作。不能只依服務商名稱或模型家族推斷能力。

## 傳送與確認

每次 AI 呼叫都必須由使用者重新發起。學習請求會傳送凍結的選區、必要的本書上下文與歷程、目前教學指令和問題。視覺學習只增加明確確認的有限區域／頁面圖片。選用 PDF 索引只傳送已確認的異常頁面；Kimi 全文準備只傳送明確選擇的 PDF；整本提問使用目前教材目錄和相關本機擷取內容，而不是整本上傳。

首次傳送區域／頁面圖片、啟動 AI 輔助索引和偵測到費用風險的操作，都需要確認服務商、模型、內容類別、圖片／頁數和風險。拒絕就不會傳送。保存的選擇只對對應 profile 和類別有效，不能允許背景工作。隱藏回答面板不會取消請求；只有明確按「停止」才會取消該請求。

Kimi 在輸入金鑰後透過不含教材內容的 `GET /models` 探測綁定中國或國際區域，沒有手動區域選擇器。只有明確的認證／區域不符才會嘗試另一區域；逾時、限流、網路和 5xx 錯誤會保留原錯誤。聊天、Files 上傳／輪詢／下載和清理都使用綁定區域。

### 本機模型邊界

Ollama 和 LM Studio 請求只允許使用數字回環位址，略過代理並拒絕重新導向。應用程式在每次推理前再次驗證模型是否確實為本機模型；Ollama 的 localhost 也可能列出雲端模型，LM Studio 也可能透過 LM Link 暴露其他裝置，因此不能只檢查主機名稱。

Ollama 文字和視覺已進行真實機器驗證。LM Studio 文字接入為實驗性功能，真實機器驗證延至 v0.2.1；本版本不承諾 LM Studio 視覺輸入。詳情見[離線本機模型](local-models.zh-TW.md)。

## 官方參考與驗證邊界

協定依據保留在英文 [AI services](ai-services.md)、[ADR 0004](architecture/0004-provider-protocols.md) 和 [ADR 0005](architecture/0005-multimodal-provider-capabilities.md)。能力註冊表變更時必須重新核對官方來源和 `last_verified`。

五個雲端服務的真實認證門禁仍未執行；現有證據主要是合成／回環協定測試，不代表目前帳號、額度、模型可用性或真實請求一定成功。
